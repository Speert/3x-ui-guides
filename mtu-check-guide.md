# Проверка оптимального MTU для VPN

## Зачем проверять MTU?

Если MTU слишком большой, пакеты фрагментируются и могут блокироваться firewall. Проверка покажет максимальный размер пакета, который проходит без фрагментации между вашим компьютером и VPN-сервером.

**Симптомы неправильного MTU:**
- Медленная загрузка сайтов через VPN
- Обрывы соединения
- Частые блокировки firewall
- Некоторые сайты не открываются

## Как проверить MTU

### С вашего компьютера на сервер

**НА ВАШЕМ КОМПЬЮТЕРЕ (MacBook/Windows/Linux):**

```bash
# Узнайте IP вашего сервера (если не знаете)
# Замените SERVER_IP на IP вашего VPN-сервера
ping -M do -s 1372 SERVER_IP

# Если пакеты проходят (0% packet loss) - MTU 1400 подходит
# Если "Frag needed" или 100% loss - MTU нужно уменьшить
```

**Для Windows:**
```cmd
ping -f -l 1372 SERVER_IP
```

### С сервера на ваш компьютер

**НА ВАШЕМ КОМПЬЮТЕРЕ узнайте свой IP:**
```bash
curl -4 ifconfig.me
```

**НА СЕРВЕРЕ проверьте (замените YOUR_IP):**
```bash
ping -M do -s 1372 YOUR_IP
```

## Расшифровка команды

- `-M do` (Linux/macOS) или `-f` (Windows) - запретить фрагментацию пакетов
- `-s 1372` (Linux/macOS) или `-l 1372` (Windows) - размер данных в байтах
- **1372 + 28 байт заголовков = 1400 MTU**

Если пакет не проходит → MTU нужно уменьшить

## Что делать если пакеты не проходят

### Метод подбора оптимального MTU

**1. Уменьшите размер пакета постепенно:**

```bash
# Попробуйте MTU 1360 (1332 + 28)
ping -M do -s 1332 SERVER_IP

# Попробуйте MTU 1300 (1272 + 28)
ping -M do -s 1272 SERVER_IP

# Попробуйте MTU 1280 (1252 + 28) - минимальный IPv6 MTU
ping -M do -s 1252 SERVER_IP
```

**2. Найдите максимальный проходящий размер:**

Начните с малого значения (например, 1252) и увеличивайте пока пакеты не начнут теряться:

```bash
ping -M do -s 1252 SERVER_IP  # MTU 1280 - работает
ping -M do -s 1272 SERVER_IP  # MTU 1300 - работает  
ping -M do -s 1292 SERVER_IP  # MTU 1320 - работает
ping -M do -s 1312 SERVER_IP  # MTU 1340 - работает
ping -M do -s 1332 SERVER_IP  # MTU 1360 - НЕ работает!
```

**Результат:** Максимальный MTU = 1340

**3. Установите найденное значение в VPN клиенте**

Округлите вниз до десятков для запаса: **1340 → 1330 или 1300**

## Установка MTU в VPN клиентах

### iOS (Shadowrocket/V2Box)
1. Откройте настройки подключения
2. Найдите параметр **MTU**
3. Установите найденное значение (например, **1300**)
4. Сохраните и переподключитесь

### Android (v2rayNG/NekoBox)
1. Настройки подключения → Дополнительные параметры
2. MTU → установите значение (например, **1300**)
3. Применить изменения

### Windows/macOS (WireGuard)

Редактируйте конфигурационный файл:
```ini
[Interface]
MTU = 1300
```

### Hiddify/V2rayN
1. Настройки → Core Settings
2. Найдите MTU setting
3. Установите значение (например, **1300**)

## 💡 Рекомендации

### Универсальные значения MTU

| MTU | Описание | Рекомендация |
|-----|----------|-------------|
| **1400** | Оптимально для большинства сетей | ⭐ Начните с этого |
| **1360** | Для сетей с PPPoE | Если 1400 не работает |
| **1300** | Консервативное значение | Если проблемы сохраняются |
| **1280** | Минимальный IPv6 MTU | 🔒 Гарантированно работает везде |
| **9000** | Jumbo Frames | ❌ **НИКОГДА не используйте для VPN!** |

### Частые ошибки

❌ **НЕ используйте MTU 9000** - вызывает фрагментацию и блокировки  
❌ **НЕ используйте MTU > 1500** - стандартный Ethernet MTU = 1500  
❌ **НЕ забывайте про заголовки** - VPN добавляет 60-80 байт overhead  

✅ **Используйте MTU 1280-1400** для VPN  
✅ **Проверяйте MTU после смены сети** (домашний WiFi → мобильный интернет)  
✅ **Устанавливайте одинаковый MTU на всех устройствах**  

## Проверка после установки MTU

**После изменения MTU в клиенте:**

1. **Переподключитесь к VPN**
2. **Проверьте работу:**
```bash
# Должны открываться быстро
curl -I https://google.com
curl -I https://youtube.com
```

3. **Проверьте что блокировки UFW стали реже:**
```bash
# На сервере
sudo grep "YOUR_IP" /var/log/ufw.log | tail -20
```

## Дополнительная диагностика

### Определение MTU пути (Path MTU Discovery)

**Linux/macOS:**
```bash
# Узнать MTU маршрута до сервера
tracepath SERVER_IP
```

**Вывод покажет:**
```
 1:  192.168.1.1                      0.5ms pmtu 1500
 2:  10.0.0.1                          5.2ms pmtu 1492
 3:  217.60.2.248                     45.3ms reached
     Resume: pmtu 1492
```

**Path MTU = 1492** → используйте MTU 1400 в VPN (1492 - 92 байт VPN overhead)

### Проверка фрагментации

```bash
# Отправить большой пакет и посмотреть фрагментируется ли
ping -M do -s 1472 SERVER_IP -c 4

# Если проходит - MTU path >= 1500
# Если не проходит - уменьшите размер
```

## Частые вопросы

**Q: Почему MTU 1400, а не 1500?**  
A: VPN добавляет заголовки (WireGuard ~60 байт, VLESS/Reality ~80 байт). 1500 - 100 = 1400 с запасом.

**Q: Нужно ли менять MTU на сервере?**  
A: Обычно нет. Меняйте только в VPN клиенте на своих устройствах.

**Q: MTU влияет на скорость?**  
A: Да. Слишком маленький MTU = больше пакетов = больше overhead. Оптимальный MTU = максимальная скорость.

**Q: Можно ли автоматически определить MTU?**  
A: Да, Path MTU Discovery (PMTUD), но многие firewall блокируют ICMP. Поэтому лучше настроить вручную.
